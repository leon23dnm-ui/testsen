# MESSAGING.md — протокол обмена сообщениями между кодером и Deviant Desktop (IDE с ИИ)

Документ описывает, как два агента (человек-кодер ↔ ИИ-агент в Deviant Desktop)
обмениваются задачами и ответами через файлы в этом репозитории.
Формат — markdown + YAML-фронтматтер, чтобы читался и человеком, и парсился машиной.

---

## 1. Каталог и структура очереди

```
docs/messaging/
├── inbox/        # входящие: сообщения ДЛЯ агента-получателя
├── outbox/       # исходящие: подготовленные, но ещё не доставленные
├── done/         # выполненные (закрытые) сообщения
├── failed/       # проваленные / отклонённые с причиной
└── INDEX.md      # реестр всех сообщений (автострока статуса)
```

Правила перемещения:
- Новое сообщение создаётся сразу в `inbox/` адресата.
- Получатель берёт файл, работает, затем переносит его в `done/` или `failed/`.
- Конкурентный захват: перед работой переименовать `MSG-xxx.md` → `MSG-xxx.md.lock`
  (второй агент увидит `.lock` и пропустит сообщение).

## 2. Имена файлов

```
MSG-<ГГГММДД>-<HHMMSS>-<отправитель>-<краткий-slug>.md
пример: MSG-20261003-141500-coder-fix-pytest-libtmux.md
```

## 3. Формат сообщения

Каждый файл начинается с YAML-фронтматтера, затем тело.

```markdown
---
id: MSG-20261003-141500-coder-fix-pytest-libtmux
from: coder            # coder | deviant-desktop
to: deviant-desktop    # адресат
ts: 2026-10-03T14:15:00Z
type: task             # task | question | review | status | handoff
priority: high         # low | normal | high | block
status: open           # open | in-progress | done | failed
branch: qwen-code-rebase
base_commit: d64c656
artifacts: []          # трогать без спроса запрещено
---

## Цель
Один абзац: что нужно получить на выходе.

## Контекст
Что уже сделано, где смотреть (пути, строки, ссылки на docs/ISSUE-*.md).

## Ограничения
- Не менять src/iski/safety/** без явного разрешения.
- Тесты должны проходить: `python -m pytest` (76 passed), ruff clean.

## Критерии приёмки (Definition of Done)
- [ ] pytest: 0 failed
- [ ] ruff check/format: чисто
- [ ] дашборд пересобран: python build_dashboard.py
- [ ] REPORT.md обновлён (если менялся статус задач)

## Ответ получателя
(заполняется тем, кто выполняет; при закрытии — сюда)
- result: done | failed
- commit: <hash>
- notes: ...
```

## 4. Статусы и переходы

```
open ──(захват .lock)──> in-progress ──> done
                              │
                              └──> failed (обязательно с reason в «Ответ получателя»)
```

## 5. Типы сообщений

| type     | смысл                                   | ждёт ответа? |
|----------|------------------------------------------|--------------|
| task     | поручение на работу                     | да           |
| question | вопрос без изменения кода                | да           |
| review   | просьба проверить diff/PR                | да           |
| status   | одностороннее уведомление                | нет          |
| handoff  | передача контекста другому агенту        | да           |

## 6. Правила для ИИ-агента (Deviant Desktop)

1. Перед началом работы прочитать этот файл и последний закрытый `done/MSG-*` —
   это актуальный контекст передачи.
2. Одно сообщение = одна задача = один коммит (или связка коммитов с одним id).
3. Не выполнять сообщение, если `status != open` или есть `.lock`.
4. Любое изменение проверять командой:
   `python -m pytest && ruff check src tests && ruff format --check src tests`
5. После закрытия добавить строку в `INDEX.md` и удалить `.lock`.

## 7. Правила для кодера

1. Ставить `priority: block`, только если работа действительно остановлена.
2. В `artifacts` перечислять файлы, которые агент НЕ должен трогать
   (например, незакоммиченные локальные правки).
3. Не редактировать чужие сообщения в `done/` — вместо этого открыть новое
   со ссылкой `"re: <id>"` в теле.

## 8. Индекс

Реестр ведётся в `docs/messaging/INDEX.md` таблицей:

| id | from→to | type | priority | status | commit | дата закрытия |
|----|---------|------|----------|--------|--------|---------------|

## 9. Быстрый шаблон нового сообщения

```bash
cd /workspace/docs/messaging
ID="MSG-$(date +%Y%m%d-%H%M%S)-coder-<slug>"
cp TEMPLATE.md "$ID.md" && $EDITOR "$ID.md"
```
