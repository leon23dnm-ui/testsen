# M0-issue 01

Где найдено (задание/тест): T22 — повторный fast-прогон V1 (`make run-m0`) после фикса `bootstrap.yaml::p0 0.0 -> 0.5` (пустой граф был дефектом конфига, исправлен).

Симптом (лог/график): все 18 комбо (eta_plast x Lambda x eta_g) → вердикт НЕ НАЙДЕН. Падают 3 критерия на каждой комбо:
- `warm_ok`: mean s_ed[-200:] = -0.0093 << theta_ed_warm=0.9 — readout ebar не трекает e_in;
- `entropy_band`: mean H = 2.59 > H_max = 2.0 — поле близко к равномерному (max log(NK)=2.77);
- `rho_stable`: max rho_j = 9.68 / 44.4 / 79.2 при Lambda = 0.1/0.5/0.9 >> rho_max = 1.0.
Проходят: activity_band (0.75 in (0,1)), no_recovery, nontrivial.
Расширенный лог тика: gate_frac=0.8, w_fro~=120.8, mask_frac=1.0, mean_g~=1.0001, mean_F_ext=0.19, eps_norm~3.6.

Гипотеза причины: параметры | спецификация.
- rho_j: веса инициализируются U(0, W_max=100) — тот же ключ задаёт bound инварианта; |w_eff| ~ O(50) на ребро => строковые суммы J=(1-Lam)I+Lam*A порядка 10-80 при любом Lam>0. Связка "init-диапазон = invariant-bound" и rho_max=1.0 взаимно несовместимы на непустом графе.
- warm_ok: e_in — случайные единичные вектора (hash-encoder), ebar = alpha @ E где alpha — нормированные нормы строк X; нет механизма, сводящего ebar к e_in за 10 warm-тиков (fast) — возможно, недостижим и за 1000.
- entropy_band: без гетерогенного входа X релаксирует к почти равномерному полю (H->max), band (0,2) ниже достижимого аттрактора.

Предложение (НЕ меняет математику без решения куратора):
1. Разделить диапазон инициализации и bound: init w_plus ~ U(0, w_init) с w_init ~ O(0.1-1) при сохранении W_max=100 как инварианта — либо пересмотреть rho_max под физику v3.0.
2. Пересмотреть theta_ed_warm / критерий warm_ok под достижимый уровень s_ed для данного encoder/readout, либо увеличить warm_ticks.
3. Пересмотреть H_max под реальный аттрактор (2.0 < log(NK)=2.77 при равномерном поле).
4. После решения — полный (не fast) прогон V1.
